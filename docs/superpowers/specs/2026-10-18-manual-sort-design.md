# 手动排序（拖拽调整顺序）设计

日期：2026-10-18
范围：错题库、知识点库（试卷库不涉及）

## 背景与目标

现状：错题、知识点列表固定按「创建时间倒序」排列（新增的排最前），用户无法自己调整顺序。

目标：让用户可以**拖拽**调整列表顺序。

- 每库（错题库 / 知识点库）各维护**一套全局顺序**，与合集、标签筛选无关。
- 保留现有「自动排序（创建时间倒序）」为默认；用户**首次拖拽后自动切换为「手动」**。
- 设置里可在「自动 / 手动」之间切换；切回自动**不删除**已存的手动顺序，便于再切回。

## 交互（核心）

- 每张卡片显示一个**拖拽手柄按钮**「⠿」。
- **必须按住手柄**才能开始拖动（普通点击/长按卡片其它区域行为不变，长按多选不受影响）。
- 按住手柄拖动时，卡片实时移动到目标位置（拖动中给出落位提示）；**松手后持久化**。
- 用**指针事件**（`pointerdown/pointermove/pointerup`）实现，桌面与触屏通用，不依赖 HTML5 拖放。

### 允许拖拽的条件

仅在「列表视图」且满足以下**全部**条件时显示手柄并允许拖拽：

- 未搜索、无标签筛选、无状态筛选、未「只看收藏」、未「只看待复习」；
- 未开启「分组」模式；
- 合集筛选为「全部」。

其余情况（含背题模式、随机复习、试卷视图）**隐藏/禁用**手柄，避免在子集视图里拖拽导致顺序语义含糊。

## 数据模型（纯函数，放 [lib.js](../../../lib.js)）

条目新增字段：

- `order: number | null`，默认 `null`，随条目存储、导出、导入。

新增纯函数：

- `sortItems(items, mode)`
  - `mode === 'auto'`：按 `createdAt` 倒序（与现状一致）。
  - `mode === 'manual'`：`order` 有值的按 `order` 升序在前；`order === null` 的（新加入、还未参与拖拽）排在最前，其内部按 `createdAt` 倒序；`order` 相同用 `createdAt` 倒序兜底。
- `materializeOrder(items)`：把当前「自动顺序」固化为显式 `order`（0..n-1），供进入手动模式时使用。
- `reorderItems(items, movedId, targetIndex)`：在整库顺序上把 `movedId` 移动到 `targetIndex`，返回**重新编号**（0..n-1）后的顺序数组；若移动后顺序无变化，返回原数组（值相等）。

`normalizeQuestion / normalizeKp`：带上 `order`（`typeof o.order === 'number' ? o.order : null`）。

## 存储

- 排序模式：存放在设置对象 `mq_settings` 中，`sortMode: { q: 'auto' | 'manual', k: 'auto' | 'manual' }`。
- 顺序本身：存在每个条目的 `order` 字段上，随条目一起存储与导出/导入，无需额外存储项。
- 首次拖拽：若该库仍为 `auto`，先对整个列表执行 `materializeOrder`，再应用本次拖动，并把该库 `sortMode` 置为 `manual`。

## 设置界面

- 设置抽屉新增「排序」小节，针对**当前库**显示两个选项：`自动（创建时间）` / `手动（拖拽调整）`。
- 切换只影响当前库；切到自动后列表恢复创建时间倒序，已存的 `order` 保留。

## 导出 / 打印 / Markdown

- 三者都**跟随当前库的排序模式**：手动模式用 `sortItems(..., 'manual')`，自动模式保持现状（现已按创建时间倒序）。

## 测试

- 单元测试（`test/lib.test.js`）：
  - `sortItems`：auto 与 manual 两种模式；manual 下 `order=null` 排最前；`order` 相同按 createdAt 兜底。
  - `reorderItems`：移到首、移到末、移到自身、上下相邻交换、目标下标越界钳制；结果为新数组且 order 被重编为 0..n-1。
  - `materializeOrder`：产出 0..n-1 且顺序与输入一致。
  - 归一化：`order` 字段保留数字、非法值归 `null`；`paperWrongToQuestion` 生成的错题默认 `order=null`。
- 浏览器验收：按住手柄拖拽跨多张卡片、松手后顺序保持；刷新后顺序保持；筛选态下手柄不出现；自动↔手动切换。

## 边界处理

- 拖回原位、或落点等于当前下标：不写盘、不重编号。
- 筛选/搜索/分组/非「全部」合集视图：不显示手柄、不允许拖拽。
- 在手动模式下**新增**条目：`order=null`，显示在最前；一旦参与拖拽会被一并重编号。
- 删除条目：不影响其它条目的 `order`（允许空洞，排序仍正确）。
- 拖动过程中触发重渲染（如状态变化）：以松手时的落点为准，避免半途状态错乱。

## 非目标（YAGNI）

- 不做「按合集/筛选视图分别记忆顺序」的细粒度顺序。
- 不做多点触控 / 多选批量拖动排序。
- 不做拖拽到合集侧栏完成「移动合集」（合集移动已有独立入口）。
