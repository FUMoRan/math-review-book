# AI 按错题整理知识点（考点体系 + 挂载）设计

日期：2026-10-20
范围：错题视图 → 知识点库；试卷视图不涉及

## 背景与目标

现状：

- 错题库（q）与知识点库（k）分开存。知识点条目字段为 `title` / `content` / `tags` / `collectionId` / `status` / `star` / `images` / `srs` / `order`（`lib.js` 的 `normalizeKp`）。
- 已有「🧠 AI 整理」：给错题**打标签 / 归入合集 / 写一句「考点 + 易错点」到错题的 `knowledge` 字段**，并按**标题精确匹配**已有知识点条目挂上 `kpId`（`applyOrganizePlan` 的 `matchKp`）。它**不会生成**知识点条目。
- 错题 ↔ 知识点目前是**单值** `kpId`；卡片上的「相关 N」用**标签交集**算（`relatedCount`）。
- 已有可复用件：`aiCall()`、`parseAiJson()`（容忍 ``` 围栏与前后废话）、`resolveCollectionPath()`（支持任意深度、自动创建缺失合集）、`addCollection()`、审阅表与撤销模式、`.modal` / `.panel.wide` 样式、`aiBusy` 忙等态。

目标：让 AI 从错题出发，先在**知识点库**里建出一套三层考点体系（学科 / 章节 / 考点），再把每道错题挂到相关考点上（**多对多**），并为真正被挂到的考点补写讲解。全程「AI 提议 → 人工审阅 → 一键应用 → 可撤销」。

## 分层与术语

| 层 | 落到哪里 | 例子 |
|---|---|---|
| 学科（一级） | 知识点库的**合集** | 高等数学 |
| 章节（二级） | 知识点库的**合集**（上一级的子） | 极限 |
| 考点（三级） | **知识点条目**，归属到章节合集下 | 夹逼定理 |

## 数据模型

- **错题**：`kpId: string\|null` → `kpIds: string[]`
  - `normalizeQuestion` 做一次性迁移：老数据 `kpId` 为非空字符串则转成 `[kpId]`，否则 `[]`；同时去重、过滤非字符串项。
  - 现有写 `kpId` 的地方同步改为 `kpIds`：`applyOrganizePlan` 的 `matchKp` 分支、AI 整理的应用逻辑与撤销快照。
- **知识点条目：不新增任何字段**
  - 讲解 → 现有 `content`
  - 层级 → 现有 `collectionId`
  - 反向关系（知识点 → 相关错题）**不落库**，一律现算：
    `kpRelatedCount(kp) = stores.q.items.filter(q => q.kpIds.includes(kp.id)).length`
  - 只存一份真相（错题的 `kpIds`），两侧不可能不一致。
- **「相关 N」语义变更**：改为只按 `kpIds` 计算，不再用标签交集，也不做标签回退。
  - 错题卡片「相关知识点 N」= `it.kpIds.length`
  - 知识点卡片「相关错题 N 道」= 现算的 `kpRelatedCount`
- **删除知识点条目**：从所有错题的 `kpIds` 中摘除该 id，避免悬空引用。
- **删除章节/学科合集**：沿用现有合集删除逻辑（其中的知识点条目落回未分类），`kpIds` 不受影响。

## AI 调用与产物

### Step 1：考点体系提议

输入：范围内错题的摘要（`id` + 题干前 200 字 + 现有标签）；知识点库里已有的 `{ 合集路径, 考点名 }` 清单（供复用判定）。

输出：

```json
[ { "subject": "高等数学", "chapter": "极限",
    "topics": [ { "title": "夹逼定理", "kpId": "k12" },
                { "title": "单调有界准则", "kpId": null } ] } ]
```

- `kpId` 非空 = 复用已有条目；AI 只能使用输入清单里给出的 `kpId`，不得编造。
- `kpId` 为空 = 新建条目。

### Step 2：挂载 + 讲解

输入：Step 1 定稿后的考点清单（每条带 `key`：复用项用其 `kpId`，新建项用生成的临时 key）+ 范围内错题摘要。

输出（`kpKeys` 的每一项是一个 **考点 key**：复用项用其 `kpId`，新建项用临时 key，形如 `tmp3`）：

```json
[ { "qid": "q7", "kpKeys": ["k12", "tmp3"], "knowledge": "夹逼定理：……" } ]
```

随后，对**本次挂载建议引用到的、且 `content` 为空**的考点输出讲解（key 同上）：

```json
[ { "kpKey": "k12", "content": "……" } ]
```

- 讲解文风沿用现有提示词：定义 + 为什么成立 + 怎么用 + 易错点，公式用 LaTeX。

### 免 Key 路径

两个步骤各自提供「复制提示词」与「粘贴 JSON」，解析复用 `parseAiJson`。

## UI 与流程

- 入口：工具栏新增「🧠 整理知识点」`#aiKpBtn`（排在现有 📷 AI 识题 / 🧠 AI 整理 / 🔍 整理工具 之后）。
- 弹层 `#aiKpModal`（`.panel.wide`），四屏状态机，复用现有取元素封装与 `.modal` 模式：

1. **设置**：整理范围（全部错题 / 当前筛选结果 / 仅未挂知识点 —— 后者指 `kpIds` 为空的错题）；冲突策略（默认「只补不覆盖」，可选「覆盖」；同时作用于 `kpIds` 合并与 `knowledge` / `content` 覆盖）；按钮：开始整理 · 复制提示词（免 Key）· 粘贴 JSON · 取消；提示语说明「会联网，错题原文将发送到配置的服务商」。
2. **体系审阅**：三层缩进列表；每行 = 勾选框（建 / 不建）+ 名称输入框（可直接改名）+ 删除按钮（删掉一个学科 / 章节会连带其下所有项都不建）；行尾标签「新建 / 复用」；底部「应用体系」→ 创建合集与知识点条目，进入下一步。
3. **挂载审阅**：每题一行 = 跳过勾选 + 题干摘要 + 考点多选 chips（可选集合 = 体系里所有进入的考点，含复用与新建）；下方单独区块「待补讲解的考点（N）」，每个考点一个 `textarea`（不按题重复出现）。
4. **应用并保存**：快照 → 写回 → 提供「撤销上次应用」。

## 应用语义（关键规则）

- **体系应用**：按学科 / 章节两级调 `resolveCollectionPath` 建合集（已存在同名则复用）；再对每个勾选的考点建条目（`kpId` 非空的复用，且**不覆盖**其既有 `content`）。
- **挂载应用**：
  - 先解析 key：把每条建议里的 `kpKeys` 映射为真实 `kpId`（临时 key 指向本次新建条目的 id，未知 key 丢弃），再按下列策略合并。
  - 只补不覆盖（默认）：`newKpIds = 去重(原 kpIds ∪ 解析后的 kpId)`
  - 覆盖：`newKpIds = 去重(解析后的 kpId)`
  - `knowledge`：仅当 AI 给了值，且（覆盖模式 或 原字段为空）时写入。
- **讲解写入**：仅写入 `content` 为空（或覆盖模式）的考点条目。
- **幂等**：重复整理时 Step 1 的复用判定按「归一化考点名 + 同一章节」命中已有条目，不新建；体系二次应用不产生重复合集。
- **撤销**：一次快照覆盖 错题 `kpIds` / 知识点条目（新增与 `content` 变更）/ 合集树，统一回滚；只针对**最近一次**应用（沿用现有撤销模式）。

## 边界与错误处理

- **无 AI Key**：走「复制提示词 / 粘贴 JSON」，不报错。
- **范围内无错题**：直接提示并停在当前屏，不发请求。
- **AI 返回非法 JSON 或结构不符**：`parseAiJson` 解析失败即报错，停在当前屏可重试；输出中未知的 `qid` / `kpId` 直接忽略。
- **考点从未被挂到**：`content` 留空，知识点卡片显示「待补讲解」。
- **学科 / 章节与同名已有合集同名**：复用，不新建。
- **考点名同名但在不同章节**：视为不同考点（复用判定要求同章节）。
- **删除知识点条目**：从各错题 `kpIds` 摘除。
- **错题被删除**：其 `kpIds` 随之消失；知识点侧反向数现算，自动保持一致。

## 测试

- `lib.js` 纯函数 + `node --test test/`
  - `normalizeQuestion`：`kpId` → `kpIds` 迁移（合法字符串 / 空 / 非字符串 / 已是数组 / 去重）
  - `normKpTitle`：归一化（trim、全角空格、大小写、内部空白折叠）
  - `planKpTaxonomy`：体系 → 两级合集 + 考点条目计划；已有同名合集 / 条目判定为复用
  - `applyKpLinks`：挂载计划 → 错题 `kpIds` 与 `knowledge`；只补不覆盖 / 覆盖 两种模式
  - `kpUsage`：统计每个考点被多少错题挂到
  - 现有 97 条用例必须全绿
- `app.js`：两个提示词、两次 `aiCall`、四屏状态机、撤销（无独立单测，靠浏览器验收）
- 浏览器验收：
  - 造三层体系 → 应用后知识点库出现两级合集 + 考点条目
  - 挂载后 → 错题卡片「相关知识点 N」、知识点卡片「相关错题 N 道」正确
  - 刷新后 `kpIds` 与合集 / 条目持久化
  - 撤销 → 错题 `kpIds`、条目、合集全部回滚
  - 删除知识点条目 → 错题上不再引用
  - 无 Key 时复制提示词 → 粘贴 → 走到审阅

## 非目标（YAGNI）

- 不做知识点自动合并 / 同义词归并
- 不做定时自动整理
- 不做知识点难度 / 权重建模
- 不改试卷视图
- 不做多轮对话式细化
- 不为「相关 N」建缓存索引（数据量小，现算足够）
- 不做标签交集回退
